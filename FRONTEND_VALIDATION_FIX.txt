Issue: Le frontend refusait les domaines sans protocole

❌ PROBLÈME
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Symptôme:
- L'utilisateur entre "outscale.com" (sans protocole)
- Message d'erreur rouge: "L'URL doit commencer par http:// ou https://"
- Impossible d'ajouter le couple

Cause:
Validation frontend trop stricte dans app/page.tsx:
```typescript
if (!url.startsWith('http://') && !url.startsWith('https://')) {
  showToast('L\'URL doit commencer par http:// ou https://', 'error');
  return;  // ❌ Bloque l'ajout
}
```

Cette validation empêchait l'utilisation du domain tracking !

✅ SOLUTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Suppression de la validation stricte du protocole:

AVANT (app/page.tsx, ligne 105-110):
```typescript
// Validation basique de l'URL
const url = newPair.url.trim();
if (!url.startsWith('http://') && !url.startsWith('https://')) {
  showToast('L\'URL doit commencer par http:// ou https://', 'error');
  return;
}
```

APRÈS:
```typescript
// Validation basique de l'URL ou domaine
const url = newPair.url.trim();
if (!url || url.length < 3) {
  showToast('URL ou domaine invalide', 'error');
  return;
}
```

Changements:
✅ Supprime la vérification du protocole
✅ Vérifie seulement que l'URL/domaine n'est pas vide
✅ Vérifie une longueur minimale (3 caractères)
✅ Message d'erreur plus générique

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ VALIDATION BACKEND (déjà correcte)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

La fonction isValidUrl() dans lib/url-utils.ts accepte déjà les domaines:

```typescript
export function isValidUrl(url: string): boolean {
  try {
    if (!url.startsWith('http://') && !url.startsWith('https://')) {
      new URL('https://' + url);  // ✅ Ajoute automatiquement https://
    } else {
      new URL(url);
    }
    return true;
  } catch {
    return false;
  }
}
```

Avantages:
✅ Accepte "outscale.com" (ajoute https:// pour valider)
✅ Accepte "https://outscale.com"
✅ Rejette les URLs invalides (ex: "abc xyz")

Donc le backend était déjà prêt, seul le frontend bloquait !
