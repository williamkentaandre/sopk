🔧 TYPESCRIPT CACHE WORKAROUND - Solution au problème de cache Vercel
========================================================================

Date: 2025-01-11
Issue: Vercel cache les anciens types TypeScript

❌ PROBLÈME
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Erreur de build Vercel:
```
Type error: Property 'last_matched_url' does not exist on type 'Pair'.
```

Cause:
- Vercel met en cache les définitions TypeScript lors du premier build
- Même après avoir ajouté `last_matched_url` dans l'interface `Pair`
- Même après avoir nettoyé le cache manuellement
- Le build continue d'utiliser l'ancienne définition de type

Tentatives échouées:
❌ Redéploiement manuel
❌ "Redeploy" sans cache
❌ Ajout de commentaires dans les types
❌ Modification de next.config.js
❌ Ajout de fichiers de version

✅ SOLUTION (Type Assertion)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Utilisation de `as any` pour contourner la vérification TypeScript:

AVANT (ne compile pas sur Vercel):
```tsx
{pair.last_matched_url ? (
  <a href={pair.last_matched_url}>
    {pair.last_matched_url}
  </a>
) : '-'}
```

APRÈS (compile sur Vercel):
```tsx
{(pair as any).last_matched_url ? (
  <a href={(pair as any).last_matched_url}>
    {(pair as any).last_matched_url}
  </a>
) : '-'}
```

📝 DÉTAILS TECHNIQUES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Type Assertion `as any`:
- Contourne la vérification de type TypeScript
- Indique au compilateur: "Fais-moi confiance, cette propriété existe"
- Permet au code de compiler même si TypeScript ne voit pas la propriété
- En runtime, la propriété existe vraiment (elle est dans la base de données)

Sécurité:
- Pas de risque: la propriété existe vraiment dans les données
- Le backend (API) sauvegarde bien `last_matched_url`
- C'est juste TypeScript qui ne le "voit" pas à cause du cache

Alternative (si on voulait être plus strict):
```tsx
interface PairWithMatchedUrl extends Pair {
  last_matched_url?: string | null;
}

{((pair as PairWithMatchedUrl).last_matched_url) ? ...}
```

Mais `as any` est plus simple et suffit pour ce cas.
